# /kata-register — 型の登録

バズ投稿から構造テンプレート（型）を抽出し、`kata-library/` に蓄積する。

前提: 作業ディレクトリ直下。Python は `.venv/bin/python`。設計上の絶対ルールは
`CLAUDE.md` に従う（特に「型に元投稿本文をコピーしない」「重複は既存型に追記」）。

---

## 手順

### 1. 入力の受け取り（いずれか）

- **キーワード収集**:
  `.venv/bin/python scripts/fetch_threads.py --mode search --keywords "<語>" --max 20 --with-replies`
- **アカウント指定収集**（相対上位方式）:
  `.venv/bin/python scripts/fetch_threads.py --mode user --usernames @aaa @bbb --per-user-top 3 --with-replies`
- **ファイル指定**: `materials/buzz/` などのファイルパスを受け取る
- **テキスト直貼り**: チャットに貼られた投稿本文をそのまま使う

> ⚠️ **型化用の収集は必ず `--with-replies` を付ける**（連投の続きまで取得して構造を見るため）。
> アカウント指定は `--per-user-top 3`。Threads収集は控えめに（週1回・20件程度）。

収集したら `materials/buzz/` の保存ファイルを読み、分析対象の連投を特定する。

### 2. 構造分析（7観点）

各バズ投稿（連投）について、次の7観点で分析する:

1. **型の分類と命名** — この型は何か（例:「ギャップ提示型」「判定チェックリスト型」）
2. **連投数と各ブロックの役割** — 何本構成で、各投稿が担う機能
3. **フックの技法** — 冒頭でどう掴むか（予告/否定/数字/問いかけ 等）
4. **読者を留める仕掛け** — クリフハンガーの切り位置、次を読ませる導線
5. **エンゲージの発生源** — 保存/リプ/共有 のどれを、どう誘発しているか
6. **心理設計** — 不安の反転/判定基準の提供/情報ギャップ 等、なぜ効くか
7. **ファネル上の役割** — 認知/教育/信頼構築/CTA前段 のどこを担うか

### 3. 型化ルール

分析を「型プロンプト」に落とす。次を厳守:

- **ブロックごとの番号付きルール**で書く。
- **フレーズ実例ではなく「機能」で記述する。**
  - ×「"エグい話するけど"で始める」
  - ○「核心を明かす予告で始める。表現は自由」
- **項目数などの数字は「素材から決める」と可変化**する（固定値にしない）。
- **クリフハンガーは「切る位置」と「次ブロックでの受け方」をルール化**する。
- **心理設計を「この型が効く理由」として明文化**する。

### 4. 重複判定

`kata-library/INDEX.md` と照合する。
**ブロック構造の骨格 ＋ フック技法 ＋ 主エンゲージ源 の3つが同じなら、
新規作成せず既存型に「バリエーション」として追記する。**
1つでも明確に異なれば新規型として作成してよい。

### 5. 保存（1型 = 1ファイル）

`kata-library/<type-slug>.md` を作成（重複時は既存ファイルに追記）。frontmatter:

```yaml
---
name: <type-slug>
category: <分類>
registered: <YYYY-MM-DD>
source_summary: <元投稿の要約1行 ※本文はコピーしない>
thread_range: <連投数レンジ 例 3-5>
hook: <フック技法>
engagement: <主エンゲージ源 保存/リプ/共有>
funnel_role: <ファネル役割>
uses: 0
---
```

本文には最低限、次を書く:

- **適合する素材の特徴**（`/kata-write` の型選択で使う。必須）
- **ブロック別の型プロンプト**（機能ベースの番号付きルール）
- **この型が効く理由**（心理設計）
- （重複追記の場合）**バリエーション** の節

最後に `INDEX.md` の表へ1行追記する。
