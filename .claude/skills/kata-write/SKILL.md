# /kata-write — 投稿の制作

素材（YouTube字幕）＋型＋共通モジュールから Threads 連投を生成する。

前提: Python は `.venv/bin/python`。設計上の絶対ルールは `CLAUDE.md` に従う。
特に **型ローテーション必須**・**CTAは投稿ごとにAIが新規生成（使い回し禁止）**・**500字は機械検証**。

---

## 手順

### 1. 素材の用意

**素材・チャンネル指定がない場合** → `AskUserQuestion` で定番チャンネルの選択ボタンを出す。

- `assets/youtube-channels.txt` を読み、チャンネルを選択肢にする。
- **1問4個までの制約があるため 3件×2問に分ける**。各問に
  「この組からは選ばない」の選択肢を必ず付ける。

選択後、そのチャンネルで:
```
.venv/bin/python scripts/fetch_youtube.py channel --channels <選択> --list
```
のランキングから動画を自動選定する。基準:

- **チャンネル中央値より明確に伸びている（相対判定）**
- **アカウント趣旨（20〜30代女性向け恋愛/男性心理/愛され/溺愛系）に合う**
- **素材化済みは除外**（`materials/` に同動画IDのファイルがあれば除く）

選定理由を明示してから字幕取得へ進む（**確認待ちはしない**）:
```
.venv/bin/python scripts/fetch_youtube.py transcript "<選定した動画URL>"
```

**直接指定も可**: YouTube URL / キーワード / ファイルパス / テキスト直貼り。
- URL → 上記 transcript
- キーワード → `fetch_youtube.py auto --keyword "<語>" --top 1`

### 2. 素材分析

保存された字幕を読み、次を把握する:
論点数 / リスト性の有無 / 理由・メカニズムの有無 / 体験談か理論か。

### 3. 型選択（ローテーション必須・スパム判定対策）

> 同型の高頻度使用でスパム判定されリーチが激減した実績がある。必ず守る。

1. `output/posts/` の直近5投稿の冒頭メタを確認する。
2. **直近2投稿で使った型は選ばない。**
3. **同日に同じ型を2本作らない**（当日の output を確認）。
4. 残った型の中から、各型の「適合する素材の特徴」と素材分析（手順2）を
   照合して選ぶ。
5. **選定理由を明示する。**

### 4. リライト

- **型プロンプト ＋ `kata-library/_common-modules.md` ＋（存在すれば）`assets/persona.md` を必ずすべて適用する。**
- 内容は素材から取る。型からは構造だけ。
  **口調・フレーズ・テーマ・数字は素材/参考から引き継がない。**
- 口調は `assets/persona.md` があればそれに従う（`_common-modules.md` の文体ルールと
  競合する場合は persona.md を優先。500字上限・アスタリスク禁止等の出力形式ルールは
  常に `_common-modules.md` に従う）。
- **CTA は本文に含めない**（後工程で連結）。
- 投稿ごとにコードブロックで分割。ページラベル（[1/3]等）は付けない。

### 5. 検証（必須）

- **機械チェック**: 一旦 output に下書き保存し
  `.venv/bin/python scripts/check_length.py <file>` を実行。
  500字超過・アスタリスク・ページラベルが1件でもあれば直す（終了コード1）。
- **同一語尾3連続なし** を目視で確認。
- **素材と似た表現の混入なし** を確認（あれば書き直す）。

### 6. CTA生成（投稿ごとに新規生成・使い回し禁止）

`assets/cta.md` の参考例を **文体・構成の文脈** として読み、今回の投稿内容に合わせて
**その都度オリジナルのCTAを新規に書き起こす**。参考例のフレーズをそのままコピペしない
（型と同じく「機能」だけ参考にする）。口調は `assets/persona.md` があればそれに従う。

- 本文の核心（何が足りない/何を解決するか）から自然に繋がる一文で始める。
- 素材にある権威性・実績（あれば）を活かす。なければ省略してよい。
- 「1日1回まで」のような頻度制約は撤廃（固定文面ではなくなったため）。ただし
  **直近の投稿とCTAの構成パターン・言い回しが似すぎないか確認する**
  （型ローテーションと同じ理由でCTAも既視感を避ける）。
- リンク誘導する場合は `assets/cta.md` にあるプロフィールリンク導線の書き方を参考にする。

長文はCTAを **独立した最終投稿** にする。短文は本文と連結して500字以内に収める。

### 7. 出力

`output/posts/<日付>_<型slug>_<テーマslug>.md` に保存。冒頭メタ（必須）:

```
- 日付: YYYY-MM-DD
- 使用型: <型slug>
- 素材出所: <YouTube URL / ファイル>
- CTA: 新規生成（参考: assets/cta.mdの参考例）
- ローテーション確認結果: <直近5投稿の型／今回選定理由>
```

続けて **投稿ごとにコードブロック** で本文（CTA連結済み）を並べる。

- チャットにも **投稿ごとにコードブロックで表示** する。
- 使用した型ファイルの frontmatter `uses` を +1 する（INDEX.md の使用回数も同期）。

---

## 完了報告

- 使用型・素材出所・CTAが新規生成であること
- ローテーション確認結果
- 機械検証がPASSしたこと
